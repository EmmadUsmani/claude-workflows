# visual-explainer — reference

Long-tail detail for the `visual-explainer` skill: section spines, the recurring component
vocabulary, two house palettes, citation formats, and the sampler page anatomy. Two subjects
run through it: the **shipped example** (how `Rack::Builder` stacks middleware, real code) and an
**invented incident** (new subdomains stay unreachable for an hour because resolvers cache the
"no such name" answer). Every name and number in the invented one is made up.

---

## 1. Prior art — read one before you build

**One example ships with the skill:** `examples/rack-builder-stack/rack-builder-stack.html`, an
`explain` page about existing code (how `Rack::Builder` turns `config.ru` into nested
middleware, read at rack/rack @ da90464). Its claims were checked with two Ruby probes run against
the cloned lib; the probes aren't shipped, but their recorded outputs are, beside the page
(`probe.out.txt`, `sim_check.out.txt`), and back every measured caption and the Fig. 2 simulator.
Its one-sheet is one-pager's `examples/rack-builder-stack.new.html`. Serve it (Phase 4) and read it first.

After that, your own pages are the best prior art. They live under `<sandbox_dir>`:

```bash
ls -t <sandbox_dir>/tickets/*/*.html <sandbox_dir>/adhoc/*/*.html 2>/dev/null | head -20
```

A new user has none yet — start from the shipped example, §8's skeleton and §3's components.
The shapes worth recognising as your collection grows:

| shape | mode | what makes a good one |
|---|---|---|
| **Mechanism** (the shipped example) | explain, existing code | verdict bullets with `file:line`, a glossary of real names, claim headings, figures captioned with probe output, a simulator checked against a script's ground truth, a "What to do with this" close |
| **Incident** (the DNS example in §2) | explain, a live problem | the verdict above everything, a reproduce-it-yourself figure the reader can drive, the cause in your own code named last, an options table with costs, commands to check it in an appendix |
| **Short form** | explain | four unnumbered sections: verdict, the one figure, the fix, how to check it — for a problem a reviewer only needs to approve |
| **Proposal** | explain, nothing built | today → the proposal → what changes for users → rollout and risks → open questions, with one simulator of the proposed behaviour |
| **Sampler** (`tickets/<name>-preview/`) | explore | a candidate grid generated by a script through the **real** pipeline, a mandatory control row, a README (§6) |

## 2. Explain mode — section spines

Headings are **full sentences with a verb and a claim**, not topic labels. Numbering appears
only when the content genuinely is a sequence. Each spine line below is an `h2`, so the
spine *is* the contents sidebar (§8).

**Mechanism** (the shipped example), h1 *"The first use is the outermost layer."*:

```
The answer                                            ← the verdict, 4 bullets with file:line
The pieces, by their real names                       ← the glossary
1 Reading config.ru only records closures
2 to_app folds the closures from last to first        ← the centerpiece figure
3 A use after a map never sees the mapped paths       ← the surprise, with a simulator
4 URLMap tries the longest prefix and moves it into SCRIPT_NAME
5 On the way out, BodyProxy defers work until the server closes the body
What to do with this                                  ← the reader's action list
  footer: sources at <sha> + the probe scripts in this directory
```

**Incident** (invented), h1 *"New subdomains stay dark for an hour because resolvers remember
that they didn't exist."*, eyebrow `Hosting · Incident explainer · 3 Feb 2026`:

```
Status and what to do today               ← verdict + the workaround, above everything
Try it: ask for a name before it exists   ← a timeline the reader drives (create time, TTL slider)
Who remembers the "no such name" answer   ← glossary: stub resolver, recursive resolver, the SOA record
The zone's SOA record sets the penalty    ← the centerpiece: zone excerpt + measured cache window
Our provisioner asks before it creates    ← the cause in our code, named last, with file:line
Options, with what each one costs         ← a table: lower the SOA minimum / reorder / pre-create
Appendix: check it yourself               ← dig commands and their real output
```

The order differs on purpose: for a mechanism the reader needs the model first; for an incident
they need the status and workaround first and the cause last. Pick the order from what the
reader has to *do*, then keep the invariants: the answer is never withheld, every claim has its
source, the figure carries a measurement, and the page ends with sources and the scripts beside
it.

Every one is a single scrolling page with no tabs. **New pages get the contents sidebar by
default** (§8), and an older page without one gets it when it is next revised.

## 3. Component vocabulary

Recurring, reusable, and worth matching so a new page reads as part of the family.

- **Masthead** — `.eyebrow` (`Hosting · Incident explainer · 3 Feb 2026`; its `::after` trails a
  1px rule to the right edge) → `h1` → lede/dek → a row of `.chip`s: mono
  `<span>LABEL</span><b>VALUE</b>`, e.g. `Severity Medium · Status Live today · Negative TTL 1 h ·
  New hosts hit 9`. `.chip.sev` red, `.chip.live` amber.
- **`.verdict`** — a bordered pre-section block stating the answer in 3–4 sentences. Amendments
  are appended in place: `<strong>Update 2026-02-05 — workaround confirmed.</strong>`
- **`.factgrid`** — a grid of `.field` label/value pairs for the subject's identifiers
  (Zone / Resolver / Record / Negative TTL / First seen).
- **`.sec-num`** — mono, letter-spaced `01` in a 1px-bordered, 2px-radius tinted box, or a round
  `.step-num` pill (`border-radius:999px`, ink bg, paper text) for a numbered procedure.
- **`.gloss`** — the glossary: a definition grid, `grid-template-columns:minmax(240px,346px) 1fr`,
  real name → one-line meaning (the shipped example's "The pieces, by their real names").
  `.gloss-item.flag dt` colours the one at fault red.
- **`.plate`** — a bordered white figure card with **corner ticks** drawn via `::before/::after`
  (9px L-shapes, 1px accent, `opacity:.55`); `.plate-title` in uppercase mono reads
  `Fig. 2 — One resolver, before and after the record exists`.
- **`.payload`** — a `<pre>` of real output (a JSON response, a `dig` answer section) with `<b>`
  around the load-bearing lines.
- **`.card.ok` / `.card.bad`** — a 3px coloured left border; used for source-A-vs-source-B and
  what-breaks-vs-what-doesn't pairs. Once a colour has a meaning, it keeps it page-wide.
- **`.readout` / `.cell`** — the live metric grid under an interactive figure
  (`Record created` / `NXDOMAIN cached until` / `Reachable from` / `Dark for`), values
  `.v.bad` red / `.v.ok` accent.
- **`.pill` / `.badge` / `.tag`** — `border-radius:999px`, `.72rem`, bold; `.pill.ok`,
  `.pill.broken`, `.badge.b-fixed`, `.tag.hi/.mid/.lo`.
- **`.callout` / `.callout.good` / `.callout.warn`** — each opens with a bolded lead-in that is a
  claim, not a label: `<b>Waiting does fix it.</b>`, `<b>Flushing your laptop's cache doesn't.</b>`
- **`table.filelist`** — the fix's file list: real path → one-line role.
- **`ul.srclist`** — raw clickable source URLs, each annotated with how you got it
  (`RFC section · normative` vs `vendor blog · not authoritative`).
- **Sortable table** — `th button{all:unset}`, sticky `thead th`, `.bar-track`/`.bar-fill`
  inline bars (`.bar-fill.hi` red, `.mid` amber), `td.num.hot` for outliers.
- **Footer** — `Sources:` at a named sha, the hand-written date, and the list of scripts and their
  output in the same dir (the shipped example's footer is the model).

**Figures.** Hand-authored **inline SVG** is the default — zero mermaid, zero canvas, zero
charting libraries. Screenshots appear as base64 `data:` evidence *underneath* an overlay,
never as the diagram itself. The SVG's `fill`/`stroke` reference the page's CSS custom
properties (`fill="var(--ok-soft)" stroke="var(--broken)"`), so diagrams theme automatically.
Every `<svg>` carries `role="img"` and a full-sentence `aria-label`.

**`figcaption` carries the measurement, not a restatement** — from the shipped example:
*"Measured by probe case 1 (`use A; use B; run app`): Ruby initialised B first (wrapping the
Proc), then A (wrapping B)."* — or, for the invented incident: *"Resolver B answered NXDOMAIN
for 59 min 41 s after the record existed (dig every 30 s); the zone's SOA minimum is 1 h."*

**Interactivity is vanilla JS in one `<script>` at the bottom of the file.** Toggles use
`aria-pressed`; sliders use `aria-describedby` to their readout. Ship presets beside a slider
(`data-preset` values for the cases that matter, e.g. **Today (1 h)**, **Proposed (5 min)**,
**Pre-created**) so the reader can jump to them. Keep
`:focus-visible{outline:2px solid var(--accent)}` and
`@media (prefers-reduced-motion:reduce){*{transition:none!important}}`.

## 5. Citation formats

Every claim carries its source, in one of these shapes:

- **Code, in a table cell:** `Rack::Builder#to_app (lib/rack/builder.rb:267-274)`;
  `urlmap.rb:43-45 · remap` (the shipped example's tables).
- **Code, quoted:** a `<pre>` whose **first line is the file path as a comment**, with the
  load-bearing line marked by a `.bad` span (or bolded) and the consequence as an inline comment:
  ```
  # app/services/provisioner.rb   (invented)
  wait_until_resolvable!(host)     # asks DNS first → caches NXDOMAIN for 1 h
  DnsRecord.create!(host: host)    # the record arrives after the "no"
  ```
- **An error:** paste the real class, message and the trimmed backtrace verbatim — e.g.
  `SocketError: Failed to open TCP connection to new-host.example.com:443 (getaddrinfo: nodename
  nor servname provided, or not known)` with the two frames of your own code under it.
- **Third-party docs and standards:** the quoted sentence in a `.quote` italic, hyperlinked to the
  **exact anchor** of the page that says it — e.g. *"The max-age=N response directive indicates
  that the response remains fresh until N seconds after the response is generated."* →
  `developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control#max-age`; for a
  standard, the RFC section anchor. Never the docs homepage, and never a quote you didn't copy
  from the page.
- **Endpoints:** the full URL, its auth posture, and a real payload excerpt with the
  load-bearing keys bolded. Pair it with a **"See it yourself"** `ul.srclist` of clickable raw
  URLs so the reader can check.
- **Runnable commands** the reader can re-run themselves: the probe and its run line (the shipped
  example's footer gives its probes' `ruby -I <checkout>/lib` line beside their recorded output);
  `dig +norecurse @<resolver> <host>` for the invented incident; a dry-run of the remediation
  (`DnsRecords::Precreate.call(dry_run: true, hosts: %w[...])`).
- **Provenance of shipped state:** branch names, PR links (`org/repo#<n>`, and what it is stacked
  on), commit SHAs with what they changed, spec counts from the run you did, log source names.

## 6. Explore mode — sampler page anatomy

The page is a decision instrument. Someone reads it, picks a candidate, and knows the exact
parameter value to implement. The running illustration below is a **thumbnail-encoding
sampler**: which quality preset and encoder should the app use for generated thumbnails?

**Page order:** h1 → a long `.lede` (`max-width:88ch`) that **defines every axis in prose**
(preset = quality + chroma subsampling; encoder = JPEG / WebP / AVIF; input = the test images)
→ `.controls` toolbar → one `<section>` per input image → click-to-enlarge lightbox.
**No contents sidebar:** generator-built samplers are exempt from §8. A hand-written `explore`
page, such as a design-options comparison, still gets it.

**A neutral, fixed surround.** When the judgement is visual, set the page background to one
flat neutral and write the reason into the CSS, so nobody "fixes" it later:

```css
/* Fixed neutral surround: artefact and banding judgements drift against a
   busy or themed background, and every decision on this page is a visual one. */
```

**Two proven grid layouts:**

- *Matrix per input* —
  `.grid{grid-template-columns:repeat(auto-fill,minmax(430px,1fr));gap:16px}`; one `<figure>`
  per input whose head is `<strong>gradient-sky.png</strong>` + `.meta`
  `2400x1600 · smooth gradient · synthetic`; the body is a table with **rows = presets** (human
  label + `<code>q72_420</code>`) and **columns = encoders**. Wide inputs get their own
  `section.wide` with a single column and a `5/2` stage aspect.
- *Cards per candidate* —
  `.grid{repeat(auto-fill,minmax(240px,1fr));gap:14px}`, one `<section>` per input whose `.sub`
  reads `screenshot-text.png · 1440x900 · sharp edges · real`.

**Every cell carries its numbers.** A `.stage` (fixed `aspect-ratio`) showing the encoded
image, then a `.card-foot` in 10.5px mono with the measured facts: `SSIM 0.986` (green above
the bar, amber below), `41.2 KB`, `−63% vs today`, encode time `38 ms`, and the **production
config string** the candidate corresponds to (`thumbnails.encoder=avif quality=72`).

**Controls** are labelled button groups that set body classes: *Encoder* (`JPEG` / `WebP` /
`AVIF`), *Zoom* (`1×` / `4× crop`), *View* (`Encoded` / `Difference ×8`), *Page theme* (`light`
/ `dark`, because thumbnails ship on both).

**Lightbox** clones the live cell node so the enlarged view keeps whatever mode is active; the
caption is the full mono parameter string —
`q72_420 · avif · speed 6 · 1200w · 38.6 KB · SSIM 0.982 · gradient-sky.png`.
The difference-map sampler shows a side-by-side `source` / `encoded` pair instead.

**A control row is mandatory.** `current` appears in every sampler, and it must fingerprint
identically to production — *"the `current` row passes no overrides at all, so it goes through
the same code path as production and is literally the thumbnail users get today"*. State the bar
for a candidate in the lede: *"the bar for any preset is: no visible banding on the gradient at
1×, and smaller than today."*

**Samplers do not embed images.** They reference real renderer/CDN URLs or relative
`renders/*.png` paths — they are local-only browsing artifacts, never published as Artifacts.
Explainers are the opposite: everything inlined as base64.

**Output convention** (the generator's job — see **sandbox-tool**): append-only timestamped
files in a gitignored `out/`, `thumbs-<%Y%m%d-%H%M%S>.html`, with the swept parameter in the
name when there is one (`thumbs-20261103-091544-q60.html` plus a `.json` sidecar). Runs sit side
by side so they stay comparable; there is no `out/v1/` or per-day directory.

**A `README.md` sits beside every sampler** and is a real document: one-line purpose ("Pick the
thumbnail preset by looking at it."), the mechanism, decision tables, a `## Run it` block, a
`## Options` env-var table, an explicit **"## Nothing here is simulated"** /
**"## Local, not production pipeline"** honesty section saying exactly which parts are the real
production chain and which are approximated, a `## What to look for` judging rubric,
operational traps, and a `## Code under test` list of real paths and PR links.

**The generator's contract** (built by **sandbox-tool**, not here): a plain script run inside
the app (`bin/rails runner`, `node`, `python manage.py shell` — whatever the repo uses), **env
vars as the entire CLI surface** (`CANDIDATES=`, `INPUTS=`, `ENCODERS=`, `QUALITY=`, `OPEN=0`),
page assembled from heredocs with every interpolated string HTML-escaped, a progress table
printed to stdout, a preflight that aborts with a remediation hint when a dependency is missing
(an encoder binary not installed), and candidates driven through the **real** production classes
— e.g. a module `prepend`ed onto the app's thumbnail service overriding only the method that
builds encoder options, so storage keys, caching and error handling stay exactly as they ship.

## 8. Contents sidebar and heading hierarchy — the default layout

Every hand-authored page, `explain` or `explore`, gets this unless the user asks for a
single-panel / no-TOC page. Sampler pages emitted by a sandbox-tool generator are exempt (§6).
An older page without one gets it the next time it is revised, not before. It is extracted from a published plan page and
trimmed to what every page needs. Validated at 1280px and 390px, light and dark, in the
fragment (Artifact) form.

**How it behaves**

- **From 1100px:** a 220px rail sits left of the reading column (`.shell` grid, centred). It is
  `position:sticky; top:0` and scrolls on its own (scrollbar hidden) when the outline is
  taller than the viewport. Only the active `h2` shows its `h3`s.
- **Below 1100px:** the rail becomes a sticky 48px bar reading `CONTENTS  <h2 › h3>  ⌄`. The
  toggle opens a drop-down panel with the full tree, every `h3` shown. Choosing a link,
  clicking outside or pressing Escape closes it; Escape also returns focus to the toggle.
- **Scroll-spy** is a rAF-throttled scroll listener, not an IntersectionObserver. It marks the
  last heading whose top has crossed `--toc-offset + 72px`, and at the bottom of the page the
  last entry wins. The active link gets `.is-active` and `aria-current="location"`, its `h2`
  gets `.is-open`, and the rail (or panel) scrolls to keep it in view.
- **Clicking an entry** smooth-scrolls to it (instant under reduced motion), focuses the
  heading (`tabindex=-1`) and `replaceState`s the hash. That entry stays **pinned** until the
  reader wheels, touches or presses a key, so a short final section isn't overridden while the
  scroll settles. Modifier-clicks fall through to the browser. Loading `#id` lands there, and
  lands again once webfonts finish loading.
- **`scroll-margin-top: var(--toc-offset)`** on every `h1`–`h3`: 24px beside the rail, 68px
  under the bar. Add to it for anything else sticky (a sticky toolbar) or for an
  `.eyebrow` above the heading.
- **Theme:** it uses only the page's tokens `--bg --surface --ink --muted --line --accent
  --mono`; map those names onto your palette. `--accent` is whatever colour means "you are
  here" (a teal works well). The panel shadow is the only literal colour. It works
  under both theme blocks unchanged.
- **Artifact-safe:** inline `<style>` and `<script>` only, no external script, no storage. The
  JS is ASCII-only: the breadcrumb separator is a `\u` escape, not the literal character, which
  matters for the fragment form.

**Heading hierarchy (the TOC is only as good as this)**

- **Exactly one `h1`**, inside the masthead `<header>`. The TOC lists it as **Overview**, and the
  eyebrow, lede, chips and `.verdict`/TL;DR sit under it before the first `h2`.
- **An `h2` per spine section** (§2). A numbered page puts `<span class="sec-num">1</span>`
  inside the `h2`, and the TOC reuses it as the entry's marker. Number only a real sequence.
- **`h3` for subsections.** Each one nests under the nearest `h2` before it in document order,
  even from a sibling `<section>`. An `h3` before the first `h2` is dropped, so don't write one.
- **`h4` for card, PR and figure titles.** They are never in the TOC. Never skip a level to get
  a smaller font; style it with a class.
- **A code path under a heading** goes in `<span class="h-path">app/models/x.rb</span>`
  inside it. It is stripped from the TOC label, as `.sec-num` is, and renders as a mono
  sub-line: `.h-path{display:block;margin-top:4px;font-family:var(--mono);font-size:12px;
  font-weight:400;color:var(--muted);overflow-wrap:anywhere}`.
- **Ids are hand-written, kebab-case and stable** (`root-cause`, `fix-api`). On a long page,
  prefix them by part (`record-eval`, `fold-call`, `map-why`, as in the shipped example).
  Keep the id when you reword the heading, because links point at it. The JS slug is only a
  fallback.
- **Headings inside a mock UI** (a fake admin page in a figure) must not reach the TOC. Put the
  mock under `aria-hidden="true"`, which it should have anyway, or `data-toc-skip`.
- **Appendices** (optional): put an `.eyebrow` (`Appendix A · check it yourself`) right above
  the `h2`, in a `section.appendix` with a 2px top rule. If you want the TOC to letter those
  entries and group them under an "Appendices" label, add a small helper to the script for it
  (the skeleton below doesn't include one), and add
  `section > .eyebrow + h2[id] { scroll-margin-top: calc(var(--toc-offset) + 36px); }`.

**Page shell.** Wrap everything in `<div class="shell">`: the `<nav>` first, then
`<main class="page">…</main>`, with the script last. The script reads `main h1, main h2,
main h3`, so all content must be inside `<main>`. The example's column is
`.page{max-width:1000px;margin:0 auto;padding-inline:20px}` with prose in
`.col{max-width:760px}`. With a wider house wrap (Style 1's 1180px), set the grid's second
column to `minmax(0, 1180px)`.

**JS** (its own `<script>` at the bottom, after any page interactivity):

```javascript
(function () {
  var toc = document.getElementById('toc'), list = document.getElementById('toc-list');
  var toggle = document.getElementById('toc-toggle'), current = document.getElementById('toc-current');
  var panel = document.getElementById('toc-panel');
  var rail = window.matchMedia('(min-width: 1100px)');
  var reduced = window.matchMedia('(prefers-reduced-motion: reduce)');

  function slugify(text) {   // fallback only: hand-write stable ids on every h2/h3
    var slug = text.toLowerCase().replace(/&/g, ' and ').replace(/[^a-z0-9]+/g, '-').replace(/^-+|-+$/g, '').slice(0, 60).replace(/-+$/, '') || 'section';
    var unique = slug, n = 2;
    while (document.getElementById(unique)) unique = slug + '-' + n++;
    return unique;
  }
  function label(h) {        // heading text minus its number and code-path decorations
    var copy = h.cloneNode(true);
    copy.querySelectorAll('.sec-num, .h-path').forEach(function (node) { node.remove(); });
    return copy.textContent.replace(/\s+/g, ' ').trim();
  }
  function makeLink(h, text) {
    if (!h.id) h.id = slugify(label(h));
    var a = document.createElement('a');
    a.href = '#' + h.id;
    var num = h.querySelector('.sec-num');
    if (!num) { a.textContent = text; return a; }
    a.className = 'numbered';
    var marker = document.createElement('span'); marker.className = 'toc-num'; marker.textContent = num.textContent.trim();
    var name = document.createElement('span'); name.textContent = text;
    a.append(marker, name);
    return a;
  }

  // h1 -> "Overview"; each h2 is a top entry; each h3 nests under the nearest h2 before
  // it in document order (even across sibling <section>s). Headings inside an
  // aria-hidden mock or a [data-toc-skip] block stay out.
  var entries = [], parent = null;
  document.querySelectorAll('main h1, main h2, main h3').forEach(function (h) {
    if (h.closest('[aria-hidden="true"], [data-toc-skip]')) return;
    var level = h.tagName, text = level === 'H1' ? 'Overview' : label(h);
    if (level === 'H3' && !parent) return;
    var li = document.createElement('li'), a = makeLink(h, text);
    li.appendChild(a);
    if (level === 'H3') {
      var sub = parent.item.querySelector('.toc-sub');
      if (!sub) { sub = document.createElement('ul'); sub.className = 'toc-sub'; parent.item.appendChild(sub); }
      sub.appendChild(li);
      entries.push({ heading: h, link: a, item: li, parent: parent, label: text });
    } else {
      li.className = 'toc-item';
      list.appendChild(li);
      var entry = { heading: h, link: a, item: li, parent: null, label: text };
      entries.push(entry);
      if (level === 'H2') parent = entry;
    }
  });

  var active = null, pinned = null;
  function setActive(e) {
    if (e === active) return;
    entries.forEach(function (o) {
      o.link.classList.remove('is-active'); o.link.removeAttribute('aria-current');
      if (!o.parent) o.item.classList.remove('is-open');
    });
    active = e;
    if (!e) return;
    var top = e.parent || e;
    top.link.classList.add('is-active'); top.item.classList.add('is-open');
    if (e.parent) { e.link.classList.add('is-active'); top.link.setAttribute('aria-current', 'true'); }
    e.link.setAttribute('aria-current', 'location');
    current.textContent = e.parent ? top.label + ' \u203A ' + e.label : e.label;
    keepVisible(e.link);
  }
  function keepVisible(link) {  // scroll the rail (or the open panel) so the active link stays in view
    var box = rail.matches ? toc : panel;
    if (!link.offsetParent || box.scrollHeight <= box.clientHeight) return;
    var b = box.getBoundingClientRect(), r = link.getBoundingClientRect(), m = 48;
    if (r.top < b.top + m) box.scrollTop -= b.top + m - r.top;
    else if (r.bottom > b.bottom - m) box.scrollTop += r.bottom - (b.bottom - m);
  }
  // Scroll-spy: the last heading whose top has crossed a line just below the sticky
  // offset. At the very bottom the last entry wins, since a short final section never
  // reaches the line. A clicked entry stays pinned until the reader scrolls themselves.
  function compute() {
    if (pinned) return pinned;
    var line = (parseFloat(getComputedStyle(document.documentElement).getPropertyValue('--toc-offset')) || 24) + 72;
    var cur = entries[0] || null;
    for (var i = 0; i < entries.length; i++) {
      if (entries[i].heading.getBoundingClientRect().top <= line) cur = entries[i]; else break;
    }
    var root = document.scrollingElement || document.documentElement;
    if (entries.length && window.innerHeight + window.scrollY >= root.scrollHeight - 4) return entries[entries.length - 1];
    return cur;
  }
  var ticking = false;
  function update() {
    if (ticking) return;
    ticking = true;
    requestAnimationFrame(function () { ticking = false; setActive(compute()); });
  }
  function setOpen(open) {
    toc.classList.toggle('is-open', open);
    toggle.setAttribute('aria-expanded', String(open));
    if (open && active) keepVisible(active.link);
  }
  function jump(e, smooth, focus) {
    e.heading.scrollIntoView({ behavior: smooth && !reduced.matches ? 'smooth' : 'auto', block: 'start' });
    if (!focus) return;
    if (!e.heading.hasAttribute('tabindex')) e.heading.setAttribute('tabindex', '-1');
    e.heading.focus({ preventScroll: true });
  }

  entries.forEach(function (e) {
    e.link.addEventListener('click', function (ev) {
      if (ev.metaKey || ev.ctrlKey || ev.shiftKey || ev.altKey) return;
      ev.preventDefault();
      pinned = e; setActive(e); setOpen(false); jump(e, true, true);
      try { history.replaceState(null, '', '#' + e.heading.id); } catch (err) {}
    });
  });
  toggle.addEventListener('click', function () { setOpen(!toc.classList.contains('is-open')); });
  document.addEventListener('click', function (ev) { if (toc.classList.contains('is-open') && !toc.contains(ev.target)) setOpen(false); });
  document.addEventListener('keydown', function (ev) { if (ev.key === 'Escape' && toc.classList.contains('is-open')) { setOpen(false); toggle.focus(); } });
  ['wheel', 'touchstart', 'pointerdown', 'keydown'].forEach(function (type) {
    window.addEventListener(type, function () { pinned = null; }, { passive: true, capture: true });
  });
  var onRail = function () { setOpen(false); active = null; update(); };
  if (rail.addEventListener) rail.addEventListener('change', onRail); else rail.addListener(onRail);
  window.addEventListener('scroll', update, { passive: true });
  window.addEventListener('resize', update);

  function landOnHash() {
    var id = decodeURIComponent(location.hash.slice(1));
    var target = id && entries.filter(function (e) { return e.heading.id === id; })[0];
    if (target) { pinned = target; setActive(target); jump(target, false); }
    update();
  }
  landOnHash();
  if (document.fonts && document.fonts.ready) document.fonts.ready.then(function () { if (location.hash) landOnHash(); else update(); });
  window.addEventListener('hashchange', landOnHash);
})();
```
