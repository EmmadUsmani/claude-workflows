# Reconciliation pass: make every cross-skill reference point at something that exists

Several agents just edited the skills under the skills directory the orchestrator names, concurrently (edit groups from `INTEGRATION_PLAN.md`, possibly plus a full rewrite of one skill). Your job is to verify every cross-reference between skills is accurate NOW, and fix the ones that aren't with minimal `Edit`s. You may edit any SKILL.md / REFERENCE.md in that directory; nothing else. Do not commit — editors share one checkout; the orchestrator commits once reconcile passes.

## Checks (do all of them, over all the skills)
1. **Named sections/phases exist.** Every reference of the form "run /X", "X Phase N", "X §Y", "X's `<section title>`", "X `--flag`", "X mode `m`" must match the target skill's current headings, argument-hint, and mode names. Build the target list first: for each skill, extract `name`, `argument-hint`, all `## `/`### ` headings, and the mode/flag words in its description. Then grep each skill for every other skill name and check each reference against that list. Fix stale phase numbers, renamed sections, and flag spellings.
2. **Autonomy vocabulary.** Mode flags should be `--report-only | --approval-gated | --autonomous` wherever a skill exposes autonomy (pr-triage, ship-pr, agent-team, and any others that mention it). A skill's `--to <stage>`-style flag is *scope* — a different axis, fine; but if it mentions autonomy modes, align the words. `prod-script`'s `diagnose|repair` are scope modes — leave them.
3. **Delegation stubs vs owners.** For each delegation stub (a compressed summary that points at an owner skill for the full procedure), confirm the owner still contains the delegated content and that the stub's decisive facts don't contradict the owner (e.g. a pinned dev-server port, DRY_RUN printing the would-be-new value, the `code-style` checklist name). Where two files state the same fact differently, the owner wins; edit the other.
4. **Routing tables.** Every skill's "When not to use / hand off" section must route a mis-landed request in one hop: check that each skill that *should* be reachable from a given entry point is listed (at minimum: bug-intake ↔ warehouse-data ↔ prod-script ↔ ship-pr ↔ pr-triage ↔ verify-in-app ↔ code-style; dev-doctor ↔ worktree-*; research-doc ↔ visual-explainer; stack-surgery ↔ gh-stack; sandbox-tool ↔ prod-script ↔ dev-doctor). Add missing one-liners using the plan's routing wording (`INTEGRATION_PLAN.md` §1 P1–P9 and each skill's routing table in §2).
5. **Outbound references of any freshly rewritten skill** (written blind to the concurrent edits; e.g. bug-intake): Phase 1 → verify-in-app `--depth` values; Phase 3 → research-doc `trace`/`design`/`--dest` values and visual-explainer `explain|explore`; Phase 4 → prod-script phase numbers; Phase 5 → ship-pr / code-style / pr-triage section names; Phase 6 → sandbox-tool. Fix each to the current truth.
6. **Length + hygiene.** Any SKILL.md over ~420 lines: move long-tail to its REFERENCE.md (create if needed) without losing content. Run the checker: `python3 skills/mine-sessions/scripts/xref.py skills` from `plugins/<plugin>/` and make sure there are no genuinely dangling skill names (ordinary hyphenated words are false positives — ignore those). Grep for session ids (`<project>__[0-9a-f]{8}`), UUIDs, and emails other than dev-seed logins; remove any.

## Output
Write `<workdir>/skill_notes/reconcile.md` (≤60 lines): every mismatch found and how you fixed it, grouped by check; anything you could not resolve (two owners disagreeing on a fact you cannot verify) as an explicit open question. Reply with ONLY the list of files you edited and the count of mismatches fixed.
