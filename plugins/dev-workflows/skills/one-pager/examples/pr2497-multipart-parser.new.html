04

Mechanism · class-method hooks

parser.rb + request.rb
# multipart/parser.rb (default_tempfile_factory, # default_bufsize: same shape) def self.default_query_parser Rack::Utils.default_query_parser end # request.rb: the default multipart parser class MultipartParser < Multipart::Parser def self.default_query_parser Rack::Multipart::ParamList end end
WHY A SUBCLASS AS THE DEFAULT

form_pairs used to pass ParamList explicitly. It now passes no query parser, so the default class returns ParamList from its hook and the default parse still yields pairs, exactly as before.

05

How an app uses it

from the added spec
no_uploads = Class.new(Rack::Request::MultipartParser) do def self.default_tempfile_factory proc { raise "no uploads allowed" } end end env["rack.request.config"] = { multipart_parser: no_uploads } req.POST # => RuntimeError "no uploads allowed"

Guarantees · rollout · later

single PR
  • No :multipart_parser set → the same pairs as before (ParamList).
  • parse_multipart keeps its signature; TEMPFILE_FACTORY and BUFSIZE stay, returned by the hooks.
  • Why no flag: nothing changes until an app puts a class in the config.
  • Later (PR body): move more settings, e.g. limits, into Parser class or instance methods.
