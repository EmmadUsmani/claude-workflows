What Builder stores

instance state · red = the surprise
WHY PROCS, NOT INSTANCES

A middleware needs the app it wraps (M.new(app)), and the endpoint is unknown until run is read, which may come last. So use defers construction; a spec pins “allows use after run” (spec_builder.rb:243).

02

Build time · request time

once vs every call
WHY EVAL IN A BINDING · builder.rb:105-106

The source says instance_eval(String) “would resolve constants differently”. The binding keeps top-level constant lookup with the builder as self, and passing the path keeps __LINE__ right.

WHY C IS SKIPPED · builder.rb:160-163

The pending map becomes a proc in @use, placed before C. In the fold C wraps App first, and that wrapped app becomes the URLMap's ‘/’ default only. Put shared middleware above every map.

04

Contract

DSL + middleware
# config.ru verbs (builder.rb) use M, *args # @use << proc { M.new(app, ...) } run app # @run = app || block map "/p" { } # @map["/p"] = block, eval later warmup { |app| } # called after to_app # a middleware def initialize(app) = @app = app def call(env) s, h, b = @app.call(env) [s, h, BodyProxy.new(b) { done }] end
  • Why a BodyProxy: call returns before the client has the body; the block runs on close (body_proxy.rb:28-36).
  • SPEC: never call each on the body; to_ary is allowed (SPEC.rdoc:251-253).
05

The fold, drawn

probe case 2
WHY LONGEST PREFIX · urlmap.rb:43-45, 71

Entries sort by path length, so '/a/b' is tried before '/a'; the rest must be empty or start with '/', so '/ab' is a 404.

06

Guarantees · gotchas

behaviour today
  • Order: written order = call order; the first use sees the raw request and the final response.
  • Built once: middleware are instantiated by to_app, not per request (spec :222).
  • Builder#call rebuilds every time; servers keep to_app's result.
  • map '/' replaces the outer run (builder.rb:251-252).
  • Why no spec for “use after map”: none exists; probe.rb case 2 is the evidence.
